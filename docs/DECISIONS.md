## 2. Value Representation (64-bit NaN Boxing)
KVM uses 64-bit NaN boxing to fit all primitive values, heap pointers, and handles into a single 64-bit `uint64_t` / `Value`.

- **Double**: Any 64-bit float whose bit representation does not match the NaN tag prefix `0x7FFC000000000000ULL`. Any NaN result generated by floating point arithmetic is canonicalized to `0x7FF8000000000000ULL`.
- **Tagged Values**: Top 16 bits set to `0x7FFC` plus 4 tag bits in bits 48..51:
  - `0x0`: `NIL`
  - `0x1`: `BOOL` (bit 0 = 0 or 1)
  - `0x2`: `INT48` (bits 0..47 store a 48-bit signed integer, sign-extended to `int64_t` on unboxing)
  - `0x3`: `HEAP_OBJ` (bits 0..47 store a pointer to a `KvmHeapObject`)
  - `0x4`: `NATIVE_HANDLE` (bits 0..47 store a handle/pointer)
  - `0x5`: `BORROW` / `BORROWMUT` (bits 0..47 store pointer, bit 47/flags mark exclusive vs shared borrow)

## 3. Register File and Frame Management
- Registers are contiguous `Value` arrays on a per-VM frame stack.
- The frame stack doubles in capacity upon overflow.
- Register pointers are re-derived after frame stack growth.

## 4. Single-Threaded Deterministic Ownership Runtime
- No garbage collector or reference counting in default objects.
- Each heap object has exactly one owning register or container slot.
- `MOVE` clears source register to `NIL`.
- `DROP` recursively drops owned child slots in reverse order.
- Frame-exit sweep drops remaining owned registers on function return.
